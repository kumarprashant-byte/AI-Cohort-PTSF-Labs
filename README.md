The shared workspace for an AI-native delivery pod — Salesforce metadata, Scopezilla outputs, decision log, sprint notes, AI delivery skills. Seeded by the [`quantum-leap-launchpad`](https://git.soma.salesforce.com/dgerow/quantum-leap-launchpad) plugin via `/ql-init-engagement`. Two update paths: the vendored `ql-*` **skills** refresh with `npx skills update` (the scheduled `skills-update.yml` workflow opens that PR for you); the **engine scripts, `AGENTS.md` conventions and CI/PR scaffold** refresh with `/ql-resync` (Claude Code, with the plugin installed).

## Setup

Prereq: **Node ≥ 22.20** (https://nodejs.org or `nvm install 22`).

Open the folder in your agent harness (Claude Code, Cursor, Codex, opencode, …) and run `/ql-setup`. It installs the tooling and wires the MCP servers in one pass: [Salesforce DX](https://github.com/salesforcecli/mcp) (read from the upstream README at runtime, since the recommended config drifts), Atlassian for Jira reporting, and Salesforce Docs for doc grounding.

(If you just want the installs without an agent, `npm run setup` covers the tooling, but you'll still need `/ql-setup` for the MCP config.)

After setup, run `/ql-ingest-scopezilla <path-to-scoping-project>` to pull in the build bundle and populate engagement details. The skill writes an `<!-- ENGAGEMENT:BEGIN -->` block at the top of this file and `AGENTS.md`, mirrors the scoping output into `./scopezilla/`, and seeds `./delivery/phase-N/` plus a kickoff entry in `./decisions/`. No Scopezilla output? Turn notes or a transcript into intents with `/ql-capture-intent` instead.

Then start building: `/ql-start-intent INT-001`. Not sure what's next at any point? `/ql-guide`. Stuck on the tooling? Ask in [#help-quantum-leap-launchpad](https://salesforce-internal.slack.com/archives/C0B8D3MV6KB).
