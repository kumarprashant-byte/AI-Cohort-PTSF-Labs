# INT-020 — OWD model: Private + criteria-based sharing rules, not Public Read-Only

**Date:** 2026-09-30 · **Intent:** [INT-020](../intents/INT-020/intent.md) · **Design:** [design.md](../intents/INT-020/design.md)

## Context

INT-020's build target reads "OWD Public Read-Only on all three objects" combined with "criteria-based sharing rule per object constraining visibility to same-Region users". The acceptance clause is exclusive: an APAC Assessor's SOQL `SELECT Id FROM Subsidy_Application__c` returns only APAC rows.

Public Read-Only grants read access to every user in the org. Sharing rules are strictly additive on top of OWD — they cannot subtract. So Public R/O + sharing rules yields "everyone reads everything, plus edit access for same-region users" — which fails the acceptance.

## Decision

**OWD is set to Private** on `Subsidy_Application__c` (Assessment__c and Assignment__c are already Private, INT-009 and INT-011). Criteria-based sharing rules per Region × object grant Read/Edit to the corresponding Regional Ops Manager role and its subordinates.

## Rationale

- The acceptance is the operative test; the build-target phrasing was loose language.
- Private OWD is the only model where "sees only APAC" is enforceable server-side (including at the SOQL layer). Anything looser leaves a leakage channel.
- Guardrail 2 ("no role-hierarchy grants across regions") is honored because each region's role branch is a separate subtree.

## Consequences

- Users holding `Assessor_Base` who are not in one of the regional role branches lose visibility to Subsidy_Application__c records. That is the intended tightening.
- System Administrator profile retains `viewAllRecords`/`modifyAllRecords`, so admin-side ops are unaffected.
- INT-014's deferred Approval Process becomes materially easier — Region-scoped visibility means the approver group is naturally the same-region Team Manager.
- No delivered intent's scope hash moves (OWD lives outside the hashed fields).
